# Verification capability placement

Load this before choosing a verification profile, data capability, or runner.

## Independent axes

Verification profile (`none`, `focused`, `targeted`, `broad`, `full`) and data capability are independent. `profile=full` does not imply `real_fullworld`.

The canonical data capabilities are:

- `qualification_fixture` — default immutable qualification product for ordinary functional, interaction, state/history, geometry, responsive, accessibility, fault/race, and similar oracles;
- `bounded_real_world` — selected real Game bytes when the oracle genuinely depends on bounded production-compatible content;
- `real_fullworld` — complete-product bytes only for complete publication/root/census linkage, generator/compiler determinism, full-product scale/performance/soak, overview/minimap consistency, release acceptance, or another explicit complete-world oracle.

Always choose the minimum truthful capability.

## Placement

GitHub-hosted protected verification owns ordinary deterministic and browser work. Candidate bytes remain inert subjects; protected `main` decides execution obligations.

Molehill-PC (`oteryn-molehill-atlas`, label `oteryn-atlas-pc`) is specialist-only for a protected plan requiring `real_fullworld`, native Windows/GPU, restricted visual review, or another approved specialist capability. Do not route ordinary coverage there merely because the suite mentions FullWorld.

Synology (`oteryn-synology-atlas`, label `oteryn-atlas`) is reserved for separately authorized trusted merged-main deployment/live acceptance. It is not a general build or E2E runner.

Unavailable specialist capacity blocks only the specialist proof that needs it. Do not substitute stale evidence, move work to a less truthful capability, or weaken the oracle.

## Evidence rules

Protected PR execution uses `pull_request_target`; Merge Queue uses `merge_group: checks_requested`. Accepted deterministic and browser retries are zero. Unknown/unowned paths fail closed. Nightly or specialist depth is additive and read-only unless a separate lifecycle explicitly authorizes otherwise.

Verification success never authorizes publication or deployment.
